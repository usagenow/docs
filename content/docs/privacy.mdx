UsageNow is local-first. Your usage data stays on your Mac unless a request to the provider is needed to get your current limits.

## What UsageNow never sends to UsageNow servers

- prompts
- source code
- project names
- file contents
- conversation content
- Claude credentials
- Codex credentials
- token counts
- quota percentages
- reset times

## At a glance

| Data | Stored locally | Sent to UsageNow |
| --- | --- | --- |
| Preferences | Yes | No |
| Provider activity (tokens, requests, model) | Kept in memory, and in the widget snapshot | No |
| Usage limits and reset times | Kept in memory, and in the widget snapshot | No |
| Claude Code credentials | No | No |
| Codex credentials | Never read | No |
| Kiro, Warp, OpenCode, Qoder, Qwen Code, Cline, and Grok Build credentials | Never read | No |
| API keys you add (DeepSeek, Kimi, OpenRouter, Ollama Cloud) | In your Keychain, on this Mac only | No — sent only to that provider |
| Prompts, responses, and code | No | No |
| Anonymous product analytics | Optional | Optional, off by default |

## What UsageNow reads

UsageNow reads only what it needs to show your usage, and only for [providers you’ve enabled](/providers#turning-a-provider-off).

- **Codex** — rate limits and plan from Codex’s own app-server, and token counts, model identifiers, timestamps, and recorded rate limits from Codex session files. UsageNow checks whether Codex’s credentials file exists but never reads its contents. [Details](/providers/codex)
- **Claude Code** — timestamps, identifiers, model names, and token counts from Claude Code session files, and the plan from Claude Code’s account profile. [Details](/providers/claude-code)
- **Kiro** — the plan, credit amounts, and reset date from the usage-limits answer Kiro writes to its own log, and the time and credits of each prompt from Kiro session files. The account identifiers in that log are never read. [Details](/providers/kiro)
- **Warp** — times, outcomes, credit amounts, and tokens per model from Warp's local database, opened read-only. The text of prompts and replies is never read. [Details](/providers/warp)
- **OpenCode** — each answer's time, model, and token counts from OpenCode's local database, opened read-only. SQLite extracts only those numbers, so the reply text stored beside them never leaves the database, and prompt tables aren't read. [Details](/providers/opencode)
- **Qoder** — each answer's time, request identifier, and credits from the transcripts Qoder writes in `~/.qoder/projects`. Prompts, replies, and tool results on the same lines are never decoded, and Qoder's sign-in is never opened. [Details](/providers/qoder)
- **Qwen Code** — each answer's identifier, time, model, and token counts from the session recordings in `~/.qwen/projects`. Messages are never decoded, and Qwen Code's sign-in is never opened. [Details](/providers/qwen-code)
- **Cline** — each API request's time, model, token counts, and the cost Cline recorded, from the tasks its editor extension saves and the sessions its CLI saves. The request Cline stored beside those numbers passes through memory and is never kept or logged; prompts, replies, and Cline's keys are never read. [Details](/providers/cline)
- **Grok Build** — each finished turn's time, models, token counts, model calls, and the cost xAI reported, from the session logs in `~/.grok/sessions`. Prompts, replies, tool calls, and the turn's result text are never decoded. [Details](/providers/grok-build)

For an [account you added](/settings#accounts), the same is read from the folder you chose. Its name is the label you typed; UsageNow never reads an account's own name or email.

Lines in session files that hold conversation content are skipped. Nothing read from them is stored beyond in-memory totals, including the [30-day history](/menu-bar#last-30-days), which is computed from the tools' own files each time and never saved by UsageNow.

## Network requests

UsageNow itself makes network requests only in these cases:

| Request | When | Goes to |
| --- | --- | --- |
| Claude usage limits | Only if you turn on the experimental setting | `api.anthropic.com` |
| Anonymous analytics | Only if you opt in, and only in a build with an analytics endpoint | UsageNow |
| DeepSeek balance | Only after you add a DeepSeek API key | `api.deepseek.com` |
| Kimi balance | Only after you add a Kimi API key | `api.moonshot.ai` |
| OpenRouter spending | Only after you add an OpenRouter API key | `openrouter.ai` |
| Ollama Cloud limits | Only after you add an Ollama Cloud API key | `ollama.com` |
| Update check | Only if updates are on, or you choose Check Now | `usagenow.com` |
| Update download | Only after you accept an update | `usagenow.com` |

For Codex, UsageNow runs the Codex app-server locally, and the app-server talks to Codex’s own services on its behalf, the same way Codex does.

An update check asks for one file — the update feed — and carries nothing about you: Sparkle's system profiling is off, so no identifier, version history, or hardware description is attached. As with any request, the server sees your IP address, which is unavoidable in fetching a file at all.

## Experimental Claude usage limits

This is the one feature that uses a credential. It’s off by default. When you turn it on, UsageNow reads your existing Claude Code access token from the macOS keychain, keeps it in memory, and sends it only to Anthropic to ask for your usage.

<Callout type="privacy">
  UsageNow never refreshes, modifies, or stores your Claude Code credentials.
</Callout>

See [Claude Code](/providers/claude-code#what-usagenow-does-with-your-sign-in) for the full list of guarantees.

## Widget snapshot

The desktop widget can’t read provider data itself. The UsageNow app writes a small snapshot of display values — usage windows, reset times, plan, most recent model, and today’s token and request counts — to an App Group container on your Mac, and the widget renders only that. The snapshot never includes prompts, code, file paths, or credentials, and it isn’t sent anywhere. See [Widgets](/widgets#how-the-widget-gets-its-data).

## Analytics

Anonymous analytics are optional and off by default. Release builds from 0.4.0 send them only while you have the setting on, and nothing about your usage is ever part of them. [Telemetry](/telemetry) documents exactly what is sent.

## Notifications and the keyboard shortcut

Notifications about limits are off by default and local: UsageNow hands macOS a title and a line of text — a provider's name, a percentage, a reset time — and nothing is sent anywhere. macOS shows them wherever your notification settings allow, including the Lock Screen.

The keyboard shortcut uses the system's hot key API, which needs no Accessibility or Input Monitoring permission. macOS tells UsageNow only that its own shortcut was pressed; UsageNow never sees anything else you type. See [Settings](/settings#notifications).

## Report a Problem

**Settings › About › Report a Problem** builds a report of what UsageNow sees — versions, screen sizes, settings, and each provider's status and limits — and shows all of it first. UsageNow doesn't send it: it opens a GitHub issue or an email with the report filled in, for you to send or not. It never includes names, emails, file paths, keys, tokens, or prompts. See [Settings](/settings#report-a-problem).

## Logs

UsageNow writes diagnostic messages to the macOS unified log. They never include tokens, credentials, prompts, conversation content, source code, or file paths from `~/.codex` or `~/.claude`. See [Security](/security#logging).

## Questions

If something in UsageNow seems to contradict this page, that’s a bug. Please report it — see [Security](/security#reporting-a-vulnerability).
