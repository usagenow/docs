title: Antigravity
description: Antigravity usage limits from the IDE or its official read-only CLI report.
---

UsageNow shows the quota windows Antigravity reports for each model group. Version **0.9.0** adds a CLI fallback, so the IDE no longer has to stay open when a compatible, signed-in official CLI is available.

## Requirements

- The **Antigravity IDE** installed, running, and signed in; **or**
- The official **Antigravity CLI (`agy`)**, signed in, version **1.x from 1.1.11 onward**. This path was verified with **1.2.2**. Unknown major versions are not assumed compatible.

UsageNow does not sign you in. Use Antigravity's own sign-in flow before asking it for usage.

## IDE source

The Antigravity app runs a language server on a loopback port and prints that port and a CSRF token in its own command line. UsageNow reads just those two arguments (via `ps`), finds the socket with `lsof`, and asks the server for the same quota summary the app’s `/usage` panel shows.

Antigravity’s limits are shared by groups of models, so each group appears as its own window — for example **5-hour · Gemini** and **Weekly · Claude and GPT**.

<Callout type="privacy" title="No credentials are involved">
  For the IDE source, UsageNow never reads the Google sign-in Antigravity saved or another process's memory. The usage request stays on `127.0.0.1`. The loopback server uses a self-signed certificate, accepted for loopback addresses only. UsageNow never calls Google directly.
</Callout>

## CLI fallback

If the IDE cannot answer, UsageNow runs the official CLI's fixed, read-only usage command: `agy -p /usage --output-format json`. This is the CLI's own usage report, not an agent conversation. UsageNow accepts only the recognized usage-report structure and never sends a prompt to a model.

The CLI handles its own authentication and service requests. UsageNow does not open its credentials, extract client secrets, impersonate Antigravity headers, or refresh Google tokens. Reports are cached for five minutes. The CLI can be signed into a different account from the IDE, so its reading is never combined with the IDE's plan badge.

## When neither source can answer

Last known readings can stay for up to a day with their original timestamp, marked stale. An expired window becomes unknown rather than a guessed 100% remaining. Open the IDE or verify your compatible CLI's own sign-in, then refresh UsageNow. Neither source provides token or model activity through this integration.

## States

| What you see | What it means | What to do |
| --- | --- | --- |
| No Antigravity section | Antigravity isn’t installed, or it’s turned off in Settings. | Install Antigravity, or turn it on in **Settings › Providers**. |
| A message asking you to open Antigravity | Neither the IDE nor the supported CLI path produced current limits. | Open the IDE, or check the official CLI version and sign-in, then refresh. |
| **Antigravity usage limits are temporarily unavailable.** | The app answered, but its reply couldn’t be used. | Wait and refresh later. |
